02 / PROVISIONING WORKFLOW

Dari service hingga aplikasi aktif

Setiap tahap disimpan sebagai event. Kegagalan dapat dilanjutkan dengan retry tanpa membuat aplikasi atau database kedua.

End-to-end provisioning pipeline Idempotent · auditable · retryable
01 Customer + Plan

Admin memilih customer dan plan berisi harga, CPU, RAM, serta database mode.

02 Create Service

Entitlement plan disalin sebagai snapshot agar perubahan plan tidak diam-diam mengubah service.

03 Select Blueprint

Repository, branch, build pack, target Coolify, env key, routing, dan cluster dipilih.

04 Queue Job

Input divalidasi, secret dienkripsi, SQL opsional dibatasi maksimal 10 MB.

05 Shared DB?

Jika plan menggunakan shared database, worker menyiapkan database dan role service.

→
06 Provision + Import

Buat role, database, permission, connection limit, lalu impor SQL secara transaksional.

07 Create Coolify App

Worker memanggil API Coolify dengan recovery tag unik untuk mencegah duplikasi.

08 Configure Runtime

Environment dikirim; DATABASE_URL dikelola sistem dan tidak dapat ditimpa manual.

09 Domain + Deploy

Hostname diterapkan, aplikasi dideploy, lalu status deployment dipantau.

10 Verify → Active

Health check dan SSL harus valid sebelum job serta service dinyatakan aktif.

05 / OPERATING BASELINE

Checklist aman untuk satu server

Baseline ini membuat model satu server sederhana: seluruh komponen berbagi jalur privat yang dapat diprediksi.

Network & securityrequired
  • BillEngine, aplikasi customer, dan PostgreSQL berada pada network yang saling terhubung.
  • Port PostgreSQL tidak dipublikasikan ke internet.
  • Coolify token dan credential provisioner hanya tersedia pada server side.
  • Dynamic middleware billing gate tidak dipasang pada domain BillEngine sendiri.
Reliability & validationrequired
  • Persistent volume serta backup PostgreSQL terjadwal dan pernah diuji restore.
  • Cluster test membuktikan BillEngine dapat mengakses PostgreSQL.
  • Aplikasi uji membuktikan DATABASE_URL dapat dipakai dari container customer.
  • Health check, SSL, job events, failed jobs, disk, dan koneksi database dipantau.
Catatan penting: test koneksi cluster hanya menguji jalur BillEngine → PostgreSQL. Sebelum produksi, tetap lakukan provisioning aplikasi uji untuk memastikan jalur Container Aplikasi → PostgreSQL juga berhasil.
